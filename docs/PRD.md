# 产品需求文档

## 1. 目标

在 VS Code 与 Windsurf 中提供一个本地编排面板，把复杂开发工作拆成多个任务，并交给不同 AI 执行器协同处理。

项目当前定位不是云端多人协作平台，而是一个可开源、可本地打包、可自己安装的开发调度扩展。

## 2. 目标用户

- 重度使用 AI 辅助开发的工程师。
- 需要把分析、规划、实现、调试、审查拆成稳定流程的高级用户。
- 希望在 VS Code 或 Windsurf 中安装本地 VSIX，而不依赖扩展商店发布的用户。
- 需要固定第三方 OpenAI 兼容 API，减少最终使用者手动配置成本的维护者。

## 3. 要解决的问题

- 单轮长对话容易上下文漂移。
- 多个子任务缺少统一调度和状态跟踪。
- 不同 AI 工具的结果难以沉淀为一个完整工作记录。
- 用户不容易判断某个执行器到底能不能真实读取或修改项目文件。
- 本地安装包、固定 API、密钥存储和安全边界缺少清晰说明。

## 4. 核心方案

扩展把工作抽象为：

- 会话：一个较大的开发目标。
- 任务：会话下的可派发工作单元。
- 执行器：负责真正执行任务的后端，例如固定 API、CLI 工具或 MCP 服务。
- 调度器：管理任务状态、队列、派发、重试、取消和自动接续。
- 工作区工具桥：为固定 API 提供受控的项目读取、搜索和写入能力。

## 5. MVP 范围

- 会话创建、编辑、删除、摘要、导出。
- 任务创建、编辑、派发、自动派发、取消、重试、删除、复制。
- 多执行器注册、状态展示、能力标签和连接管理。
- 每执行器独立队列。
- 面板和侧边栏树视图。
- 结果、产物、修改文件、日志和流式输出展示。
- 固定 OpenAI 兼容第三方 API 接入。
- 固定 API 工具调用测试和安全自检任务。
- 开源发布所需的 README、英文 README、发布说明、清单、安全策略和贡献指南。

## 6. 非目标

- 云端多用户协作。
- 自动代码合并与冲突解决。
- 企业级权限系统。
- 私有 IDE 工具协议的原生实现，例如 Windsurf/Cascade 私有协议。
- 承诺任意模型或任意第三方网关都能稳定完成真实代码修改。

## 7. 验收标准

- 从源码运行 `npm run verify` 通过。
- `npm run vsix` 能生成可安装的 VSIX。
- VS Code 与 Windsurf 中都能打开主面板。
- 固定 API 可注册、可测试，并能明确展示工具调用能力状态。
- 安全自检只写入 `.ai-orchestrator/self-check.md`。
- 文档能说明下载、安装、固定 API、执行器能力、安全边界和发布流程。
